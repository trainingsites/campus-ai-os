# Student Communications

Write any type of student communication — onboarding, check-ins, progress nudges, re-engagement, feedback requests, congratulations, and testimonial requests.

## Setup Required

Kernel preamble §1 applies: `references/kernel-preamble.md`.

## Before You Start

1. Read the resolved `voice` context — communications must sound like the owner/teacher
2. Read the resolved `brand` context — communication style
3. Read the resolved `icp` context — who the students are
4. Read the resolved `offers` context — what programs they're enrolled in
5. Check the relevant employee's `memory.md` for student context

## Inputs

The user provides:
- **Communication type** — see types below
- **Context** — which program, how many students, situation
- **Specific student** (optional) — name, situation, history

## Communication Types

| Type | Purpose | Tone |
|------|---------|------|
| **Welcome / Onboarding** | First impression after enrollment | Warm, exciting, action-oriented |
| **Check-in** | How's it going? Do they need help? | Caring, specific, low-pressure |
| **Progress Nudge** | They haven't engaged recently | Encouraging, not guilt-tripping |
| **Re-engagement** | Inactive for 2+ weeks | Direct value reminder, fresh start offer |
| **Feedback Request** | Ask for course/program feedback | Specific questions, easy to answer |
| **Congratulations** | Completed a milestone | Celebratory, what's next |
| **Testimonial Request** | Ask for a testimonial/review | Grateful, specific prompts, low friction |

## Steps

### Step 1: Identify the Situation
- Which program or course is this for?
- Where are the students in their journey?
- What's the goal of this communication?

### Step 2: Write the Communication

For each email/message:
- **Subject line** — 3 options
- **Opening** — personal, specific, acknowledges their situation
- **Body** — the purpose of the email (short — 150-250 words)
- **CTA** — one clear next step
- **Sign-off** — matches the owner's style

### Step 3: Sequence (if applicable)

If writing a multi-email sequence (e.g., onboarding):
- Map the student journey: Day 1, Day 3, Day 7
- Each email has ONE job — don't overload
- Build from welcome → orientation → first win → deeper engagement

## Output

Save to `outputs/YYYY-MM/comms/[type]-[context]/`:
- Individual email files or a sequence document

If an email platform is connected via MCP, offer to create drafts.

## Rules

- Every communication should feel personal, not automated
- Never guilt-trip inactive students — lead with value
- Match the owner's teaching voice exactly
- One CTA per email — don't ask them to do 3 things
- Testimonial requests: make it easy — provide specific prompts, not open-ended asks
